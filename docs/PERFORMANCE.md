# 性能实测记录

**版次说明：下列数据属于 2026-10-23 晚间多图标改版之前的单图标版本，不能直接代表当前 1.1.0 的每设备独立图标、新左右键交互与 ZEN65 查询版本。新版完成构建、25 项核心/协议测试、17 项原生集成和 8 项真实设备 WPF 集成，没有重跑 20 分钟性能测试。原始数值和二进制指纹保持原样。**

本次正式测量于 **2026-10-23 22:08:56～22:29:58（Asia/Shanghai）** 完成。无目标对照实际持续 30.186 秒；托盘与面板各连续测量超过 600 秒，使用同一监测进程 PID 63156，没有中途重启或更换目标。测量脚本正常结束，结果 `Error=null`，测试进程已退出。

## 条件与口径

- Windows 11，系统版本 `10.0.26100.0`，测量进程可见 16 个逻辑处理器。
- .NET 10 Windows x64 自包含 Release 发布程序；冻结副本位于 `artifacts/perf-final-bin`。
- 新建 `artifacts/perf-profile`，没有使用或修改正常用户配置；每个进程启动后预热 10 秒，切换面板后也预热 10 秒。
- 自动刷新开启，周期为默认 60000 毫秒，由应用的 Win32 SetTimer 驱动。外部 PowerShell 脚本每约 5 秒采样进程计数器与只读原生状态；采样脚本的循环不属于应用刷新调度。
- CPU 表内“机器占比”按 `CPU 秒 ÷ 墙钟秒 ÷ 16 × 100` 计算；同时列出不除以 16 的单核口径。外部采样器自身 CPU 不计入；应用处理只读采样消息的开销计入主进程。
- Working Set 与 Private Memory 为主进程采样均值，单位为 **MiB（1024² 字节）**。不能将主进程内存当成包含所有硬件辅助进程的总内存。
- 硬件辅助进程 CPU 使用应用导出的累计 CPU 秒，在阶段起点和终点做差分；已经包含实际厂商查询与发现工作，不只统计驻留主进程。

监测对象来自真实 Windows 发现结果，而非模拟设备：

| 目标 | 实际读取路径与结果 |
| --- | --- |
| ROG Harpe Ace Mini（OMNI） | 已确认的 OMNI 配对身份和只读电量查询，测得 46%；测量期间也真实出现读取取消/超时，保留历史电量。 |
| 2.4G Wireless Receiver | 仅 Windows 已有设备属性；系统未公开有效电量，显示不支持，本体连接状态未知。没有凭接收器存在宣称外设已连接。 |

## 空闲区间与定时器

无目标对照的 7 个样本中，原生宿主均报告刷新定时器停止，采样时也未发现辅助进程。主进程累计 CPU 没有可见增量。此对照只有 30 秒，不能冒充另一次 10 分钟空载测试。

以下“空闲区间”按样本端点筛选：相邻约 5 秒（4～6 秒）、辅助进程累计完成数不变、两端 `ActiveProbeCount=0` 且系统进程快照没有活跃辅助进程。它是采样估计，不能证明整个间隔绝无工作。

## 内存、异常与辅助进程

托盘前 2 分钟 Working Set 均值为 102.32 MiB，2～4 分钟为 146.65 MiB，后续三个 2 分钟段依次为 151.63、153.12、154.02 MiB。可见初期明显上升，末段接近平台，不能将整个阶段描述为“零增长”。

面板五个 2 分钟段 Working Set 均值依次为 155.98、155.22、156.73、162.71、162.66 MiB；对应 Private 均值为 95.22、93.59、96.18、106.95、107.69 MiB。中后段有一次抬升，最后两个分段的 Working Set 接近。线程和句柄有升有降，面板末尾句柄 774，低于开头的 783，没有观察到单调无界增加。**20 分钟不足以证明长期无泄漏，也不足以排除缓慢内存增长；长时间压力和堆分析仍待验证。**

测量期间日志记录了 **7 条 ROG 协议取消/超时错误**。错误日志受限量策略约束，此数字是日志条数，并非所有底层 I/O 超时的精确总数。最终快照仍保留 46%，`IsHistorical=true`、读取状态为 Timeout；最近查询为 22:29:40，最近有效电量时间仍为 22:22:38，没有因失败改成 0% 或刷新成功时间。失败原因没有得到实物侧确认，不能据此推断鼠标关机或断开。

辅助进程的 `TimeoutCount=0` 只表示该统计口径内没有父进程截止时间/终止计数，**不表示没有协议超时**。托盘阶段完成 33 次探测，面板阶段完成 36 次；加上预热时的探测，最终累计 72 次，终点无活动辅助进程。

`PeakChildWorkingSetBytes=0` 在本环境中没有得到有效峰值，必须视为**未知**，不能解释为辅助进程零内存。5 秒采样一共捕获 9 个活跃辅助进程观察值，其中单个 Working Set 最大为 49.65 MiB；短命进程可能在两个采样之间完成，因此这个观察值不是严格峰值、平均总内存或可靠上限。主进程与辅助进程的同时总内存仍待更高精度的专门测量。

## 证据与复测

源码工作区中的证据：

- `artifacts/performance-results.json`：各完整阶段的汇总和条件。
- `artifacts/performance-results.samples.json`：249 个原始样本。
- `artifacts/performance-analysis.json`：空闲段、2 分钟分段、错误日志计数和四个二进制 SHA-256。
- `artifacts/performance-timeout-state.json`：实际超时期间保存的历史值快照。
- `artifacts/perf-profile/monitored/`：测试专用配置、状态缓存、累计硬件指标和限量日志。

测量冻结副本与当时最终发布目录的 `PeripheralPower.exe`、主程序集、Core 和 Hardware 程序集 SHA-256 已逐一核对一致。主程序集 SHA-256 为 `B282DD3935DBB3C81554420FBD81C9708B613E2FE5B16EEFA39F0BEEE6A3786D`；完整指纹见分析 JSON。只比较 apphost EXE 不足以区分托管程序集修订。

退出所有应用实例后，可以重新执行（输出和配置目录必须使用新路径）：

```powershell

  -DiscoveryFile ./artifacts/actual-discovery.json `
```
