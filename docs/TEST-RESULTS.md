500 轮合成异常压力：每轮队列归零、活动读取归零；同设备最大并发 1；1.1.0 最终 Release 记录线程 **21→21**、句柄 **315→315**，Private bytes **13,533,184→16,232,448**。这仅是短时合成压力，初始运行时/JIT 内存增长不能视作泄漏，也不替代持续实机异常测试。

单设备读取超时由独立 helper 处理，其他设备可先显示结果；系统级 SetupAPI 发现则是一轮共用操作。如果驱动让整轮发现阻塞，达到时限后结束该发现进程，本轮各目标会显示发现失败并保留历史值。这个系统级枚举故障边界不能写成“任何驱动异常都不影响其他目标”。

本轮原生集成发送真实 Win32 消息，检查隐藏宿主、真实 SetTimer 创建与销毁、关闭定时器后丢弃旧 WM_TIMER、NIN_SELECT 唯一左击入口（仅前置面板）、重复右键直接进入全局设置、缓存悬停、设备事件、睡眠消息恢复合并、TaskbarCreated 重建、第二真实进程 mutex 与 WM_COPYDATA。HKCU 自启开启/关闭、被 StartupApproved 禁用及未知状态的检查使用真实注册表，finally 恢复测试前状态。没有真实重启 Explorer、注销或让机器休眠，相关实机场景仍待验证。

本轮多图标变更额外验证：有效设备替换入口图标、未知/隐藏目标没有独立图标、设备 ID 在排序和电量更新后稳定、移除图标的迟到消息不再响应、多图标 Explorer 恢复、16/20/24/32/48 像素渲染、透明角、绿色电量环随档位比例变化，以及历史值不显示绿色实时环。每个 DPI 复用渲染目标；预热后连续 120 次电量/历史态更新，在最终回收后 USER/GDI 资源没有持续增长。此短测不能替代数小时资源压力测试。

## 上一版单图标的持续性能

以下数据采自本轮多图标改版之前、22:29:58 结束的单图标冻结版本，**不能直接代表当前多图标与新点击交互版本**。本轮完成构建、25 项核心/协议测试、17 项原生集成、8 项真实设备 WPF 集成和脚本语法检查，没有重新运行 20 分钟性能测试。旧证据与其二进制指纹继续保留；如需新版完整测量，应使用已修订的性能脚本另建配置和输出目录。

旧版由 `scripts/Measure-Performance.ps1` 采集：先 30 秒无目标对照，随后默认 60 秒周期、3 个从实际 Windows 枚举记录选出的目标，仅托盘连续 600 秒，然后同一进程显示简洁面板连续 600 秒。目标分别为 ROG OMNI、通用 2.4G 接收器和旧枚举记录中的虚拟 HID；第三项在最终分组中已不存在，用于观察缺失目标的失败状态，不能称为三个已验证的实体外设。每 5 秒采样，主进程 CPU 加上独立 helper 累积 CPU 差分；两种 CPU 口径分别报告单核百分比和按逻辑处理器归一百分比。

最终测量于 2026-10-23 22:29:58 正常结束，报告 `Error=null`。本机有 16 个逻辑处理器；表中 CPU 是主进程及查询 helper 合计，内存仅为主进程，单位 MiB。

主进程内存有净增长，不能据此宣称长期无泄漏。5 秒采样可能漏过短命 helper，其退出后的峰值内存字段为 0，按“无法取得”处理，不能理解为不占内存。原始结果位于 `artifacts/performance-results.json`、`artifacts/performance-results.samples.json`，详细条件、趋势、空闲段统计及限制见 [性能实测](PERFORMANCE.md)。未完成的旧试跑不能算作 10 分钟通过。
